NON-FUNCTIONAL REQUIREMENTS

Purpose
Functional Requirements answer:
What must the system do?
Non-Functional Requirements answer:
How well must the system do it?

NFR-01 — Usability
Requirement
The system shall provide a simple and intuitive shopping experience.
Success Criteria
Users can understand the application without training.
Primary actions are clearly visible.
Navigation is straightforward.
Users can complete an order in minimal steps.
Rationale
The application is intended to simulate a modern e-commerce experience.

NFR-02 — Visual Design
Requirement
The system shall present a modern, professional storefront appearance.
Success Criteria
Clean layout
Consistent spacing
Consistent typography
Professional product card design
Shopify-inspired aesthetic
Rationale
The application serves as a portfolio project and should demonstrate UI/UX awareness.

NFR-03 — Performance
Requirement
The system shall load quickly in modern web browsers.
Success Criteria
Homepage loads within a few seconds on typical internet connections.
Product catalog renders without noticeable delay.
Status transitions occur smoothly.
Rationale
Fast feedback improves perceived quality.

NFR-04 — Responsiveness
Requirement
The system shall support desktop, tablet, and mobile screen sizes.
Success Criteria
Product cards resize appropriately.
Text remains readable.
Navigation remains usable.
No horizontal scrolling on common mobile devices.
Rationale
Modern users access websites from multiple device types.

NFR-05 — Browser Compatibility
Requirement
The system shall function in current major browsers.
Supported Browsers
Chrome
Edge
Firefox
Safari
Success Criteria
Core functionality works consistently.
Layout remains usable across supported browsers.
Rationale
GitHub Pages applications should be broadly accessible.

NFR-06 — Maintainability
Requirement
The application shall be organized using a clear project structure.
Success Criteria
Separate folders exist for:
css/
js/
data/
docs/

Rationale
Improves readability and future enhancements.

NFR-07 — Transparency
Requirement
The system shall clearly indicate that it is a simulated e-commerce application.
Success Criteria
Informational banner displayed on homepage.
Notice is readable and non-intrusive.
User is not misled into believing purchases are real.
Rationale
Supports ethical and transparent portfolio presentation.

NFR-08 — Accessibility
Requirement
The system shall support basic accessibility practices.
Success Criteria
Semantic HTML used where appropriate.
Images include alternative text.
Buttons are keyboard accessible.
Text contrast remains readable.
Rationale
Accessibility is a standard expectation for modern web applications.

NFR-09 — Reliability
Requirement
The application shall provide predictable behavior during simulated ordering.
Success Criteria
Order status transitions occur in correct sequence.
Order confirmation displays correctly.
Application does not enter invalid states during normal use.
Rationale
Predictable behavior improves user trust.

NFR-10 — Deployment Simplicity
Requirement
The application shall be deployable through GitHub Pages without additional infrastructure.
Success Criteria
No backend required.
No database required.
Application runs as static assets.
Rationale
Supports free hosting and portfolio accessibility.
